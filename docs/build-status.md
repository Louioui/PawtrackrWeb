- Staff reservation reads and writes previously validated catalog prices with `Math.round(price * 100) !== price * 100`, which is false for most cent values in binary floating point (19.99, 8.95, 0.07). Services saved at those prices through live settings were withheld from booking options and rejected with HTTP 422 on create. A contract test walks every cent price from $0.00 to $10,000.00 and confirms that whatever the settings validator accepts is bookable. Verified with `npm test` (56 passing), typecheck, and a production build; not re-verified against the hosted project.
- The CI workflow triggered only on `main`, but the repository's default branch is `Master`, so it had not been running on pushes or pull requests. The triggers now name `Master`. `npm run lint` is still unconfigured (it opens the interactive ESLint setup prompt) and is not part of CI.

- Migration `0016_enforce_visit_availability.sql` moves salon operating hours and groomer shift rules into a `BEFORE INSERT OR UPDATE` trigger on `public.visits`, so a staff token writing through the Data API can no longer skip the checks in `POST /api/reservations`. It checks active reservations only, rechecks an update only when it moves or reactivates the visit, and rejects when the time zone or hours are unusable. It raises `PW001` (hours), `PW002` (shift or time off) and `PW003` (settings), which the reservation API returns as HTTP 422. `npm run test:migrations` applies all sixteen migrations to local PostgreSQL 14 and covers hours in UTC and `America/Los_Angeles`, shift containment, time off, completed shifts, a skipped daylight-saving shift start, status progression after hours are narrowed, reschedule and reactivation, unusable settings, and a direct write under the `authenticated` role. **Not applied to the hosted project.** Known limits: existing rows are not revalidated, and adding time off or narrowing hours does not flag reservations already booked.
