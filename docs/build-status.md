## Next implementation sequence

1. Expand the real Auth and Data API check across staff roles and data mutations, and verify Storage policies with authenticated requests before using real records.
2. Replace sample PIN and demo client links with verified staff and pet-parent sessions. Derive tenant access from active membership on every server request; the browser's selected salon is a filter, not authorization.
3. Connect the authenticated staff reservation API to a staff calendar, then add salon time zones, schedules, and a separately authorized public booking flow. The database exclusion constraint is the final concurrent overlap gate for assigned groomers; the demo disk-ledger check still cannot prevent simultaneous requests from separate processes.
4. Connect Stripe Billing and POS to verified webhook events. Keep recorded app checkout totals distinct from settled revenue until refunds and payment states are reconciled.
5. Add authenticated photo delivery, real messaging, durable offline mutation replay, and source-backed production analytics. Re-run browser, migration, security, and failure-mode tests against that stack.

The project is still in progress. Green demo tests and a successful build do not prove the missing production capabilities.
