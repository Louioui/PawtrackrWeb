## Production flows added on November 9–10, 2026

These pieces are verified in temporary PostgreSQL 14, unit tests, and built-server browser checks. **Migrations 0016–0022 are installed on hosted PostgreSQL 17.11, and public booking is verified through the real anonymous Data API. Owner onboarding still needs a real hosted Auth fixture, and Stripe has not been exercised.**

- **Self-serve salon provisioning (0017 + 0020).** The exposed `public.provision_salon` is a caller-context `SECURITY INVOKER` wrapper granted to `authenticated` only; its private privileged implementation takes the owner from `auth.uid()`, and no argument can name another user or salon. A user with any staff row cannot provision again. New salons start `trialing`. `POST /api/onboarding` additionally requires a confirmed email. Local tests cover invalid slug and zone, binding of the new owner to the new tenant, the second-salon refusal, a duplicate slug, anonymous refusal, and wrapper privileges.
- **Public online booking (0018).** Anonymous callers get two functions and no table access. `public_booking_slots` lists 30-minute start times where at least one active groomer is free; `public_book_appointment` picks the groomer, reuses a client only when phone digits and name both match, and inserts through the same availability trigger and overlap constraint as staff bookings. Limits: at least 60 minutes ahead, within 90 days, 4 upcoming online bookings per phone per salon, 60 online bookings per salon per hour. The API adds a per-process, per-address rate limit, which is not shared across server instances. Bookings are confirmed immediately as `booked`; there is no staff-approval step, no customer cancel or reschedule, and no confirmation message is sent.
- **Hosted public-booking proof.** A temporary `America/Los_Angeles` salon exposed 18 valid 30-minute starts for a $75, 60-minute service through an anonymous publishable-key RPC call. Booking 09:00 local returned a confirmation with the database price, service, zone, and reference but no groomer or internal IDs. Availability then withheld all starts whose 75-minute service-plus-buffer window overlapped that booking, and a second booking at 09:00 failed with `PW022`. Deleting the salon cascaded the temporary client, pet, visit, staff, config, and catalog records; exact follow-up counts for all production tables and `auth.users` were zero.
- **Salon-local calendar.** `GET /api/reservations?date=` now treats the date as a salon-local day and returns the zone and the UTC bounds it used. The staff calendar renders times, labels, and day navigation in that zone and opens on the salon's own today. A salon without a valid zone is shown in UTC.
- **Stripe settlement (0019).** `transactions.settlement_status` is separate from checkout `status`. A trigger lets the API roles move a checkout only from `unsettled` to `pending` by attaching a PaymentIntent; `settled`, `failed`, and `refunded` are written only by `public.apply_stripe_payment_event`, which is granted to `service_role`, records each event id once, and marks a payment whose amount or currency differs from the recorded checkout as `failed`. The webhook route returns 400 for a missing, forged, altered, or stale signature and 503 when unconfigured.

- **Connected-appointment landing page (`src/app/page.tsx`).** Replaces static prototype module labels (`MODULE A • /portal/[salon-slug]`), decorative alert badge strips, and unbenchmarked competitor latency claims with an interactive 3-perspective hero (`Pet Parent`, `Salon Team`, `Owner`) sharing one sample appointment (`Bello`), a 6-stage lifecycle bar (`Requested` through `Follow-up`), an Availability Intelligence valid/blocked rule inspector, a controlled pre-check-in care-note disclosure, an interactive Data Confidence state inspector (`Updated recently`, `Checking live`, `Offline / Stale`, `Demo mode`), and a Now / Next / Later maturity breakdown. `TopNav` now places `Salon sign in` in the horizontal mobile bar below `sm` so 390 px phone headers do not wrap. Verified with `tests/e2e/landing-page.spec.ts` (3 browser & WCAG 2.1 AA axe tests at 390 px and 1280 px) and `tests/e2e/analytics.spec.ts` (8 browser & visual snapshot tests).
