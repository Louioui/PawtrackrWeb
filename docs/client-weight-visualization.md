# Client weight history visualization

The client portal reads a pet's recorded `weight_history` from the current demo store. The chart shows observation dates on a time-proportional horizontal axis and weight in pounds on a labeled vertical range. Its lower bound never falls below zero, including for a small positive observation. It uses the actual recorded observations, sorted by date; invalid dates and nonpositive weights are excluded, and the latest entry wins when a date is duplicated. The profile header, text above the chart, and dated log use that same validated history. The header labels the latest weight as a dated observation, avoiding an unsupported claim that it is the pet's current weight. The log gives exact values without hover.

With one observation, the portal shows the latest value and says there is no trend yet. With no valid observations, it shows an explicit empty state. The chart does not imply a veterinary diagnosis or target weight. It is illustrative demo profile data until authenticated client records are available.

A mobile-width axe audit scans the client page for WCAG 2 A/AA and 2.1 A/AA rule violations. It exposed unlabeled before/after photo comparison sliders; each now has a pet- and visit-specific accessible name. A browser test focuses a slider and verifies that Arrow Right and Arrow Left change its value. These checks remain an automated baseline, not a substitute for screen-reader review.

`tests/weight-history.test.mjs` checks sorting, invalid data, duplicate dates, elapsed-time positioning, and the nonnegative chart domain. `tests/e2e/client-weight.spec.ts` checks the four-observation chart and log at a 390 × 844 viewport, a 320 px chart and page layout, a deliberately conflicting undated profile weight, a small positive-weight axis, the single-observation state, and an unknown-client state that does not reveal another profile. These checks cover data-to-view agreement and layout bounds, not clinical interpretation or a pixel baseline.
