# Pawtrackr Master Workflow Registry (`WF00–WF40`)

This document is the canonical cross-workflow specification for Pawtrackr. Every screen, API route, and database function operates as an allowed state transition on a shared domain record rather than an isolated page.

## 1. Shared Architectural Rules

1. **Single Spine — The Visit**: Almost every workflow creates, advances, pauses, reconciles, or audits a `visit` record. A visit is `completed` **only** when three independent facts hold: (a) service finished, (b) payment settled (or `$0` authorized), and (c) collector verified & pet released.
2. **Recorded ≠ Settled ≠ Delivered**:
   - Payments separate `recorded` → `pending` (provider accepted) → `settled` (verified signed webhook) / `payment_unknown` / `failed` → `refunded`.
   - Messages separate `prepared` → `queued` → `provider_accepted` → `delivered` / `failed` / `opted_out`. Failed messages never mutate appointments.
3. **Append-Only History (`public.workflow_events`)**: Original financial, care, schedule, report, payroll, and correction events are never overwritten. Corrections append a new event referencing the original record version, actor, role, reason, and approver.
4. **Shared `WorkflowContext`**: Moving from an operational queue (`WF12`), profile, or calendar into a detail workflow preserves `{ salonId, role, date, sourceRecordType, sourceRecordId, sourceVersion, workflowId, returnPath, filters }`.
5. **Capability Honesty**: Every capability (`online_booking`, `staff_calendar`, `card_payments`, `text_messages`, `report_cards`) explicitly reports `ready`, `partly_ready`, `not_connected`, or `preview_only`.

## 2. Shared Domain Records & Versioning

| Record | Primary Table | Tenant Key | Versioned / Immutable Rule |
| :--- | :--- | :--- | :--- |
| **Salon (`Business`)** | `public.businesses` + `public.business_configs` | `id` / `business_id` | `booking_status` (`draft`, `published`, `paused`), `subscription_status`, `operating_model`, `trial_ends_at`. |
| **Staff Membership** | `public.staff_members` | `business_id` | 6 roles: `owner`, `manager`, `front_desk`, `senior_groomer`, `groomer`, `bather`. Bound to `auth.uid()`. |
| **Station Resource** | `public.salon_stations` | `business_id` | Physical `table`, `tub`, `cage_dryer`, or `van`. Protected by GiST exclusion against concurrent active visit overlap. |
| **Staff Shift** | `public.staff_weekly_shifts` + `public.staff_shifts` | `business_id` | Precedence: `time_off` > dated `scheduled` override > recurring `staff_weekly_shifts`. |
| **Client & Pet** | `public.clients` + `public.pets` | `business_id` | Identity, pickup contacts, behavior tags (`biter`, `matted`, `senior`), weight log, vaccination evidence. |
| **Visit** | `public.visits` | `business_id` | `version` incremented on mutation; `booking_idempotency_key` prevents duplicate online bookings; `is_test_booking` isolates setup verification. |
| **Transaction & Settlement** | `public.transactions` + `public.stripe_webhook_events` | `business_id` | Cent-exact invariant (`subtotal - discount + tax + tip = amount`); `settlement_status` mutated only by verified webhook RPC. |
| **Workflow Event** | `public.workflow_events` | `business_id` | Append-only (`UPDATE` and `DELETE` rejected by trigger). Records actor, role, before/after state, reason, and metadata. |
